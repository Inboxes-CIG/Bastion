# Logs, audit & dashboard

## Access logs

Bastion writes two formats:

| File | Format |
|---|---|
| `/var/lib/bastion/logs/access-YYYY-MM-DD.jsonl` | one JSON object per request |
| `/var/lib/bastion/logs/access.log` | combined log format (nginx-style) |

JSONL fields:

```json
{
  "time": "2026-11-24T14:00:00+01:00",
  "client_ip": "203.0.113.10",
  "host": "app.example.com",
  "domain": "app.example.com",
  "site_id": "…",
  "method": "GET",
  "path": "/api/users",
  "status": 200,
  "bytes": 1234,
  "duration_ms": 12,
  "blocked": false,
  "block_reason": "",
  "country": "DE",
  "user_agent": "…",
  "referer": "…",
  "proto": "HTTP/2.0",
  "admin": false
}
```

- Rotation: daily
- Retention: `logging.retention_days` (default 30), older files removed on startup
- An in-memory ring buffer (`logging.max_memory`, default 10000) for fast queries
- Admin requests are logged but excluded from site statistics

### Logs in the GUI

**Logs** with filters:

- Site/domain
- `blocked=true/false`
- Status code
- Search across path, client IP, host
- Limit
- Daily file selector
- Hide admin requests

API: `GET /api/v1/logs?site=…&blocked=true&status=404&q=…&limit=200&file=access-2026-11-24.jsonl&hide_admin=true`

## Audit log

The audit log lives in PostgreSQL (`audit_logs`) and is shown under **Audit** in the GUI.

Recorded:

- All mutating API requests (`POST`, `PUT`, `PATCH`, `DELETE`) with action `create`/`update`/`delete`
- Successful (`login`) and failed (`login_failed`) logins
- Automatic 404 bans (`auto_ban`)

Fields: time, user/email, action, resource, resource ID, method, path, status, IP, details.

The **Vorgang** column shows a readable description generated by the backend (currently in German), e.g.:

- `Tenant "Customer A" angelegt`
- `Site "app.example.com" geändert`
- `Location "/api" angelegt`
- `Zertifikat "example.com" ausgestellt`
- `IP-Eintrag "203.0.113.10" angelegt`
- `Cache geleert`
- `MFA aktiviert`
- `auto_ban` entries with details `blocked after repeated 404 responses`

Audit search also matches these details.

Not recorded: read-only GET requests (except login).

## Dashboard

`GET /api/v1/stats` returns:

| Area | Content |
|---|---|
| Counters | Sites, certificates, users, tenants, GeoIP rules, templates |
| `expiring_certs` | Certificates expiring within 30 days |
| `metrics` | Total requests, blocked/allowed, status distribution, block reasons, top sites, blocked countries, uptime, RPS |
| `traffic_24h` | Same aggregates for the last 24 hours (from JSONL files) |
| `system` | CPU, RAM, disk, load, uptime |

- `traffic_24h` is cached for 30 seconds.
- `metrics` is based on the in-memory ring buffer since startup (or since loading recent logs).
- `system` reads `/proc/stat`, `/proc/meminfo` and `statfs`.

## Useful commands

```sh
# Latest requests
tail -f /var/lib/bastion/logs/access-$(date +%F).jsonl | jq .

# Top status codes
jq -r '.status' /var/lib/bastion/logs/access-$(date +%F).jsonl | sort | uniq -c | sort -rn

# Blocked requests
jq -c 'select(.blocked==true)' /var/lib/bastion/logs/access-$(date +%F).jsonl | tail

# Audit (PostgreSQL)
sudo -u postgres psql -d waf -c "SELECT created_at, user_email, action, resource, status, ip FROM audit_logs ORDER BY created_at DESC LIMIT 20;"
```
